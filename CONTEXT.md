# MODPACK

Updated 2026-11-21. Project context for maintaining, testing, and sharing a Minecraft modpack centered on Create and Create Aeronautics. Full and Lite should both join the same dedicated server. Lite is for friends with older hardware, including machines with 4–8 GB of total RAM. Some friends use Legacy Launcher. Quinn uses Prism for local testing.

## Baseline

- Minecraft **1.21.1**, NeoForge **21.1.266**. The November 16 mod list includes **Create 6.0.10**, **Create Aeronautics 1.3.2**, **Sable 2.0.6**, **Sodium 0.8.13**, and **Iris 1.8.14-beta.1**. Versions changed during later troubleshooting, including a Sable downgrade test. Capture the current working Full instance before treating these as release pins.
- Overworld terrain and biomes use **Regions Unexplored + Tectonic**. Terralith is outside the current stack. The client moved from Distant Horizons toward Voxy. The November 21 server log shows **Voxy Server Side 0.22.0**.
- The main client test machine in the performance threads had an **i5-8400, RTX 3060 Ti, and 16 GB RAM**. Dedicated server profiling used a **Xeon E5-2690 v2** host. An **i5-1135G7 Zenbook with 8 GB RAM on Ubuntu** is a candidate host. Its performance with this pack needs a test run.

## Full, Lite, and Server packaging

Proposed workflow. Start from a known-good Full instance. Use one Git repo and one packwiz manifest to pin the loader, mods, configs, and shared changes. Generate all three downloads from the same release tag. The packwiz migration and build script are pending.

| Path | Purpose |
|---|---|
| `pack/pack.toml`, `pack/index.toml` | Pack and loader metadata, plus the index generated by `packwiz refresh` |
| `pack/mods/` | Pinned `.pw.toml` entries with `client`, `server`, or `both` side metadata. Account for unmatched local JARs during staging. |
| `pack/config/` | Configs distributed with the pack |
| `pack/kubejs/` | Shared KubeJS scripts and data. The fluid patch already uses this layout. |
| `pack/scripts/` | Reserved for any CraftTweaker `.zs` scripts the pack ships. CraftTweaker supplied the fluid audit dump. |
| `profiles/lite/exclude.txt` | Verified client-only exclusions, keyed by `.pw.toml` filename |
| `profiles/lite/options.txt` | Lite graphics defaults |
| `build.py` or `build.ps1` | Proposed build entry point. Stage in a clean directory, apply profile differences, and export. |
| `dist/` | Generated releases. Ignore in Git. |

| Build | Contents | Distribution |
|---|---|---|
| Full | Shared gameplay and dependencies, client optimizations, visual extras | `.mrpack` for Prism |
| Lite | Same gameplay and client optimizations, with lower graphics defaults and tested visual exclusions | `.mrpack` and a ZIP if friends need a manual installation |
| Server | Shared gameplay and server-side tools and configs, including Chunky for pregeneration | Server ZIP or packwiz-installer in server mode |

- Start Lite with shaders off and lower graphics settings. Keep client optimizations such as Sodium and ImmediatelyFast. Test visual cuts against the exact loader and dependency set. Apply graphics keys selectively if updating an existing `options.txt` so players keep their keybinds.
- An **E4All** session from Full rejected a Lite client with a missing **Particular** key. Keep the matching Particular version in both clients while the host requires it. Re-test on the dedicated release before making it an exclusion. Keep Create, Aeronautics, shared integrations, and recipe changes on the same version across builds.
- Python was suggested for filesystem operations and ZIP packaging on Windows and Linux. PowerShell fits a Windows-only build workflow. Packwiz owns the mod pins either way. The Ubuntu host can consume the built server ZIP without running the build script.
- If there is a working CurseForge export, import it with `packwiz curseforge import <zip>`. For a plain JAR folder, `packwiz curseforge detect` can match CurseForge files. Compare exact versions with the working instance and retain anything the importer misses. Keep the live world, player data, and host-specific settings in the deployment directory. Boot the staged Server and join once from clean Full and Lite installs before release. ## Recipes, tags, and fluid compatibility

The fluid thread used `crafttweaker.log` to inspect the pack and produced a **KubeJS** ZIP. Quinn reported no other KubeJS scripts or datapacks at that point. The ZIP contains six fluid tags, six recipe overrides, and one server script. Its intended behavior is to let multiple fluid IDs satisfy the same recipe input. Fluids keep separate registry IDs, so combining them in a tank would require a conversion path.

| Shared tag | Fluid IDs |
|---|---|
| `c:crude_oil` | `tfmg:crude_oil`, `createdieselgenerators:crude_oil` |
| `c:diesel` | `tfmg:diesel`, `createdieselgenerators:diesel` |
| `c:gasoline` | `tfmg:gasoline`, `createdieselgenerators:gasoline` |
| `c:ethanol` | `createdieselgenerators:ethanol`, `createaddition:bioethanol` |
| `c:plantoil` | `createdieselgenerators:plant_oil`, `createaddition:seed_oil` |
| `kubejs:hydrogen` | `tfmg:hydrogen`, `createbb:hydrogen` |

The overrides cover the three TFMG crude-oil distillation recipes, TFMG's gasoline mixing and hydrogen bucket filling, and Create: Broken Bad's methanol mixing input. The server script removes the duplicate Create Crafts & Additions seed-oil pressing recipe and leaves Diesel Generators' plant-oil route. Molten steel stayed outside the patch because the mods use different mB per ingot. Blood already had a bridge in the audit, and potion compatibility was left open. **In-game verification is pending.** Load the patch in a test instance, check recipe errors, and run both crude oils through the applicable DG and TFMG machines. Test the other affected recipes and seed pressing before including it in a tagged release. ## Worldgen and gameplay

- Initial exploration showed structures spawning too often and similar structures close together. **Structurify** was logged with overlap prevention and `1.4` global spacing/separation during one test. Tune specific `structure_set` entries on a fresh test world where global adjustments are too broad, and compare locations with the same seed before applying changes to the shared pack.
- **Cataclysm Expeditions** tests found a portal arrival that killed the player immediately, shared destination-dimension behavior, and gaps in gate coverage. The death cause is unknown. **Stellarity Enlightened** was incompatible in this pack. Enderscape and Nullscape were suggested as alternatives. The End and Nether overhaul choice is still open.
- **Farmer's Delight** is part of the pack. Nutrition or unique-food progression should give a reward that justifies cooking effort. Nutritional, Nourished, and a custom unique-food bonus were discussed without a final selection. Keep modded food compatibility in scope. Create Ambush, Hostile Skies, Cataclysm encounters, and dungeon loot were also discussed as ways to give Create equipment and airships a role in exploration.
